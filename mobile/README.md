# Recipe Hub — iPad / iPhone PWA

レシピ検索・URL取り込み・統一表示を、ホーム画面から起動できるWebアプリにしました。Safariのツールバーを出さずに独立した画面で使えます。App Storeの配布やApple Developer登録は不要です。

## ホーム画面に追加

1. 公開URLをSafariで開き、必要に応じてChatGPTアカウントでサインインします。
2. Safariの共有メニューで「ホーム画面に追加」を選択します。
3. 「Webアプリとして開く」が表示される場合はオンにし、「追加」を押します。
4. ホーム画面のRecipe Hubアイコンから起動します。

サーバーは常時公開されるため、PCを起動しておく必要はありません。ユーザー本人のみがアクセスできる設定です。保存データはD1にあり、同じ公開アプリではiPad・iPhoneから同じレシピを参照できます。

検索・レシピ取り込みにはインターネット接続が必要です。サービスワーカーは画像アイコンと画面用ファイルのみキャッシュし、個人のレシピデータや認証されたHTMLは保存しません。完全オフライン動作は提供しません。

## 機能と制限

材料・調理時間・作り方・出典の統一表示、料理名と食材のAND検索、サイト・時間の絞り込み、調理時間順、URL取り込み、永続保存。

クラシル、DELISH KITCHEN、クックパッド、楽天レシピ、キッコーマン、白ごはん.comの指定ドメインを対象にします。Recipe JSON-LDが公開され、robots.txtで取得が許可されているページだけ対応します。サイトによって情報が取得できない場合があります。実サイトの取得成功はテスト環境で未検証です。

Web横断検索はサーバーの `BRAVE_SEARCH_API_KEY` 設定が必要です。キーなしでもURL取り込みと登録済み検索は使えます。キーは公開ソースに書かず、公開先の秘密の環境変数として設定してください。

## 開発

```sh
npm install
npm run db:generate
npm run build
npm test
```

`worker/index.js` はCloudflare WorkerのAPI、`public/` はPWA画面、`db/schema.ts` はDB定義、`drizzle/` は生成マイグレーションです。ビルドはPWAファイルをWorkerに埋め込み、`dist/server/index.js` を生成します。公開設定は `.openai/hosting.json`。レシピ本文を推測で補わず、欠落値は記載なしと表示します。

## 定期取得

毎朝6時（日本時間）のクラウドタスクが、アプリを閉じていても収集を実行します。キッコーマン、DELISH KITCHEN、つくおき、Just One Cookbookの公開サイトマップから少量ずつ発見し、1回につき各サイト最大4件、合計最大16件を取得します。ほかの掲載サイトは手動URL取り込みに対応しますが、自動巡回には含めません。robots.txtとCrawl-delayを確認し、最低1秒の間隔を空けます。拒否・取得失敗・構造化データ欠落は記録し、認証回避は行いません。

サイトマップの巡回位置と取得待ちURLをD1に保存し、翌日に続きを処理します。成功URLは30日後、失敗URLは7日後に再試行。重複登録は更新になり、同時実行は排他します。日本時間の毎朝6時を区切りとする同じ収集期間内の再実行は、既存の結果を返します。1サイト当たり1回のサイトマップ読取は2ファイルまで、索引は6MBまで、レシピ一覧はストリームで100件ずつ読み、文書の途中位置を保存する保守的な初期設定です。最初から全サイトの全レシピを収集する仕様ではありません。

取得状態は `GET /api/crawl/status`、収集実行は `POST /api/crawl/run`（JSON `{}`）です。本人だけが利用できるSiteのアクセス境界で保護します。未認証の外部公開はしないでください。ルーチン更新はデータだけを変更し、再公開は不要です。

### クラウドタスクからのアクセス

各実行でSitesの `get_site` を呼び、同じSiteがactive・owner・owner-privateであることを確認し、`current_live_url` と返却された `siwc_bypass_bearer_token` を利用します。サービス資格情報はそのSiteにだけ `OAI-Sites-Authorization: Bearer ...` ヘッダーとして送信します。資格情報をソース、ログ、タスク本文に保存しません。公開レシピサイトの読取にはこの資格情報を送信しません。

`node scripts/run-crawl.mjs` を起動し、非表示の標準入力で `{"origin":"確認した公開URL","token":"その実行で取得した資格情報","action":"run"}` を送信します。レスポンス後、`action:"status"` で読戻し、最終実行時刻と件数を確認してください。収集対象と上限はサーバー側で固定し、タスクから任意URLを指示しません。失敗時はエラーを報告し、アクセス制限の回避、対象サイトの拡大、公開範囲の変更を行いません。

## 料理ブログの取り込み

nozomiの「つくおき」（cookien.com）とNamiの「Just One Cookbook」（www.justonecookbook.com）をURL取り込み・Web検索・定期巡回の対象に追加しました。後者のレシピ本文は英語で、原文のまま保存します。出典と作者を保持し、画像は掲載元URLを参照します。ログインや取得制限は回避しません。現在は確認済みのドメインのみ許可します。未知のブログURLは自動では巡回しません。

## レシピの翻訳

レシピ詳細の翻訳元・翻訳先を選び「翻訳する」を押します。日本語、英語、簡体字・繁体字中国語、韓国語、フランス語、スペイン語、ドイツ語、イタリア語、ポルトガル語に対応。タイトル・説明・分量・材料・手順を翻訳し、作者・出典・原文を保持します。画面の操作表示と検索対象は従来どおり日本語・原文です。翻訳元は掲載元から初期選択し、違う場合は変更できます。

外部のMyMemory公開APIにレシピ本文のみ送信します（APIキー不要）。アプリ内翻訳はブラウザから直接送信して各利用者の利用枠を使います。CSPでこのAPIのみ接続を許可し、Cookieや認証情報を送信しません。サーバーの翻訳APIも登録済みレシピのみに限定して保持しています。提供元の無料利用上限や混雑で翻訳できない場合は原文を表示し、理由を案内します。「Google翻訳で開く」ではレシピ全文を2500文字ずつに分けてGoogle翻訳に送り、別画面で表示できます。切り捨てはしません。翻訳結果はブラウザのメモリ（サーバーAPI利用時はWorkerの一時メモリ）で再利用し、永続保存はしません。翻訳先の好みのみ端末に保存します。長い本文はUTF-8のバイト数で分割します。機械翻訳のため分量・温度・加熱時間は原文も確認してください。

## 手入力・レシピファイル

上部の「手入力・ファイル」から、料理名・材料・作り方を入力して保存できます。調理時間、分量、作者、メモは任意。登録済みレシピと同じ一覧・検索・絞り込み・翻訳を利用できます。

PDF・Word（.docx）・UTF-8テキスト（.txt）、1ファイル10MB以内に対応します。ファイルを端末で読み取り、読み取り結果を自動で入力欄に反映し、「材料・分量」「作り方」、飾り付き見出し、英文の見出し、見出しと本文が同じ行の場合にも対応します。見出しがない場合も、分量の記載や番号付き手順、調理文から入力欄へ振り分けます。読み取り中に利用者が修正した欄は保持します。保存前に内容を確認・修正してください。文字データの抽出だけで材料・手順が見つからないPDFは、自動で画像OCRでもう一度読み取ります。読み取りに失敗した場合は理由と自動再読み取りボタンを表示します。

日本語CIDフォントのPDFに必要なCMapと標準フォントをPDF.jsと同じバージョンからビルド時に同梱し、アプリ自身から配信します。材料名と別行にある分量、折り返した材料グループ・番号付き手順、複数ページに対応します。作者名とメモを振り分け、末尾のURL・著作権表記は手順から除外します。

PDFは100ページ、抽出テキストは10万文字まで。文字データがないページや画像主体のページは、Tesseract.jsの日本語＋英語OCRで読み取ります。ページを最大約400万画素で描画し、1ページずつ処理してメモリを解放します。OCRワーカーはPDF全体で再利用し、終了時に停止します。暗号化PDFには対応しません。読み取りに失敗しても、手入力したレシピに元ファイルを添付して保存できます。PDF.js、Mammoth、Tesseract.jsのブラウザ・ワーカーを自己配信します。OCRエンジンと公開言語データは、同じアプリのR2内に保存した検証済みの公開ファイルから配信し、ファイル・画像・認識文章は端末内で処理します。初回は通信と時間が必要です。選択ファイルの変更・取り外しで中断し、遅れて完了した結果は入力欄へ反映しません。

保存時にレシピ本文をD1、元ファイルをR2のFILESへ保存します。レシピ詳細のリンクから元ファイルをダウンロードできます。ファイルも既存の本人限定アクセスで保護され、実行可能なファイルとして画面内表示しません。失敗時は入力を保持し、新規添付の片付けを試みます。登録IDで重複送信を抑制します。

アプリ復帰時に更新を確認し、入力途中のレシピがなければ新しい画面を読み込みます。既に開いていた古いバージョンは、最初の一度だけ画面を再読み込みしてください。

### OCRデータの初期設定

`npm install`、`npm run build`で固定バージョンのOCRエンジン・日本語/英語データのSHA-256マニフェストを生成します。初回公開後、`node scripts/install-ocr-assets.mjs` を起動し、その実行でSites `get_site`から取得した `origin` と `token` を非表示の標準入力へ渡してください。登録済みSHAと一致する公開ライブラリだけを本人限定APIでR2へ保存し、5ファイルすべてをダウンロードしてSHAを照合します。レシピや資格情報を外部へ送りません。保存したデータは以後の更新でも維持され、利用者の端末から外部CDNへ接続せずにOCRできます。
