# Recipe Hub

複数のレシピサイトを、材料・分量・調理時間・作り方の共通フォーマットで検索・表示する日本語Webアプリです。Python 3.12以上だけで起動できます。外部ライブラリのインストールは不要です。

## 起動

```sh
python app.py
```

ブラウザで http://127.0.0.1:8000 を開きます。スマートフォン・タブレットにも対応する画面です。サーバーを実行するPC上で使えます。GitHubのリポジトリURLはアプリの公開URLではありません。

## 使い方

1. 「URLから追加」でレシピページのURLを入力します。
2. タイトル・作者・出典・画像・分量・調理時間・材料・手順を共通フォーマットに変換します。
3. 料理名・材料を検索し、サイトや調理時間で絞り込みます。空白で区切った検索語はAND検索です。
4. 詳細画面で材料と手順を確認し、「元のレシピを見る」から出典を開きます。

データは `data/recipes.db` にSQLiteで保存され、再起動後も残ります。同じURLの取り込みは更新になります。取得できない値は「記載なし」と表示し、推測で補いません。初期状態に架空のレシピは含めていません。

## Web横断検索を有効にする

自動のキーワード横断検索には [Brave Search API](https://brave.com/search/api/) のキーが必要です。アカウント作成・料金確認は各自で行ってください。キーがなくてもURL取り込みと登録済みレシピ検索は使えます。

macOS / Linux:

```sh
export BRAVE_SEARCH_API_KEY='YOUR_API_KEY'
python app.py
```

Windows PowerShell:

```powershell
$env:BRAVE_SEARCH_API_KEY='YOUR_API_KEY'
python app.py
```

`.env.example` は設定名の見本です。`.env` を置くだけでは読み込まれません。キーはサーバー側だけで使用し、ブラウザに送信しません。検索ごとにAPIを1回呼び、最大10件の対応サイトURLを取得して登録します。Web検索後の画面は検索語と現在のフィルターに一致する登録済みレシピ全体を表示します。検索APIは有料になる場合があります。

## 対応範囲

許可ドメイン：`www.kurashiru.com` / `delishkitchen.tv` / `cookpad.com` / `recipe.rakuten.co.jp` / `www.kikkoman.co.jp` / `www.sirogohan.com`。

対応は「そのドメインのすべてのページが取得できる」という保証ではありません。ページに [Schema.org Recipe](https://schema.org/Recipe) のJSON-LDがあり、robots.txtが取得を許可し、ログインなしでHTMLを取得できることが条件です。会員限定・動的描画だけのページ・構造化データのないページ・取得制限のあるページはエラーになります。サイト固有のHTML解析や認証回避は行いません。実サイトでの取得成功は、この初期版のテスト環境では未検証です。

材料の文字列は掲載元の表記を保持します。単位換算や人数変更は行いません。HowToSection内の手順を順番に展開し、画像の不正なURLスキームを除去します。料理の内容・画像・権利は掲載元に帰属します。利用するサイトの条件を確認し、転載や大量取得を目的に使わないでください。

## テスト

```sh
python -m unittest discover -s tests -v
node --check public/app.js
```

構造化データの変換、複数サイトの統合検索、未知の調理時間の扱い、URL制限、robotsの拒否、再登録、APIと永続化を検証します。外部サービスの応答はモックにしているため、検索APIの課金は発生しません。

## 公開について

初期版は個人用のローカルアプリです。GitHub PagesではPythonバックエンドが動かないため、コードをアップロードするだけでは公開できません。外部公開する場合は認証・レート制限・HTTPSを備えた実行環境を用意してください。個人用サーバーをそのままインターネットに公開しないでください。
